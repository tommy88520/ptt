# 交接公式（PTT 專案）

目標：下一個 session（可能在另一台機器、沒有這次對話、也沒有這台的記憶）只讀 `HANDOFF.md` 就能接著做，而且不漏東西。

## 1. 先把工作收乾淨
- `git -C ~/dev/ptt status -sb`：沒 commit 的先 commit（不 commit 的話在第 2 段寫清楚是什麼、為什麼留著）；`git log origin/main..main` 要是空的（都 push 了）。
- 改過程式的話確認**已經部署**：`./deploy/deploy.sh` 跑過、3200 回 200。還沒部署就在第 1 段寫明。
- 改過 launchd plist 的話，`deploy/` 的正本跟 `~/Library/LaunchAgents/` 的要一樣。

## 2. 從這次對話逐條抓（這步決定會不會漏）
**一則一則看使用者這次的每個訊息**，每一句都要落到下面某一格，落不到就是漏了：

| 抓什麼 | 寫到哪 |
|---|---|
| 做到一半的事（檔案、做到哪、下一步） | HANDOFF 第 2 段 |
| 我問了、使用者還沒回的（附我的建議） | 第 3 段 |
| 下次要確認的事（部署後要看的、過幾天要回頭看的） | 第 4 段 |
| 使用者講的新規則／偏好（**原話**） | 第 5 段；穩定的（講第二次、或說「以後都…」）→ CLAUDE.md「使用者的規則」 |
| 做完的事（一行一件＋commit） | 第 6 段 |
| 發現但沒修的 bug、外部問題 | 第 7 段 |
| 之後要做、但不是下個 session 的事 | CLAUDE.md 最下面「待辦」表加一行 |

## 3. 改寫 HANDOFF.md
- **只寫這個專案（PTT）的事**。同一個 session 順手做了別的專案的事 → 寫進那個專案自己的 `HANDOFF.md`，這份不要提。
- **整份改寫，不是往下加**。固定 7 段：1 版本／2 進行中／3 等使用者決定／4 下次要看／5 使用者新規則／6 最近做完／7 已知問題。
- 第 1 段：`git log -1 --format='%h %s' -- . ':!*.md' ':!docs' ':!.claude'`（只看程式，不看文件 commit）、部署了沒、三個服務的狀態。
- 第 6 段只留最近兩週；更早的刪掉。
- **全長 ≤100 行**（`wc -l HANDOFF.md`）。寫不下＝細節放錯地方。
- 這次的**細節**（過程、數字、使用者原話、查證經過）寫成一段 `## 🚩 YYYY-MM-DD HH:MM：標題`，插在
  `docs/HANDOFF_ARCHIVE.md` 最上面（開頭說明行的下面）。HANDOFF 只放摘要。

## 4. 其他文件
- `CLAUDE.md` 只在「每次都用得到」的東西變了才改：鐵律、使用者的規則、環境表、常用指令、坑、待辦。
- **架構變了一定要同步 `README.md`**（它是給人看的架構說明；2026-10-12 才發現通道、資料庫帳號、webhook 三處過期）。

## 5. 自我檢查（全部成立才 commit）
- [ ] HANDOFF 7 段都在、≤100 行
- [ ] 第 1 段的 commit 跟 `git log` 對得上，部署狀態寫了
- [ ] 這次每個使用者要求，不是在第 6 段（做完），就是在第 2／3／4 段或待辦表
- [ ] 沒有把 `.env.local` 的值、webhook 網址、token 寫進任何文件（**這個 repo 是公開的**，也不要寫其他專案的內部細節、別人的名字）
- [ ] 沒有動到同一台機器上其他專案的東西（動了就去那個專案自己的交接文件記一筆）

## 6. 提交與回報
- `git add -A && git commit -m "交接：<一句話>" && git push`（只有文件的話不用部署）。
- 回報使用者 ≤6 行：第 2、3、4 段的重點。
